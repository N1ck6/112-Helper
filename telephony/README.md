# Этап 2 — SIP-звонок

## Что здесь реализовано

- Два SIP-аккаунта: `alice` (1001) и `bob` (1002) — PJSIP endpoint/auth/aor.
- Dialplan `[internal]`: набор 1001↔1002 соединяет два софтфона.
- **Echo-тест (набрать 600)** — проверка SIP+RTP с ОДНИМ софтфоном:
  сервер повторяет ваш голос обратно. Это самый быстрый способ убедиться,
  что голос реально ходит туда-обратно, не разыскивая второго человека.
- **Milliwatt-тест (601)** — эталонный тон 1004 Гц, проверяет только
  направление "сервер → телефон" отдельно от микрофона/кодека звонящего.

## Как это работает

PJSIP разделяет один "аккаунт" на 3 секции неспроста:
- `auth` — пароль, которым софтфон логинится (REGISTER);
- `aor` (Address of Record) — куда Asterisk слать INVITE для входящего
  звонка на этот аккаунт; заполняется автоматически после REGISTER;
- `endpoint` — политика (кодеки, какой контекст dialplan применяется).

Когда alice набирает `1002`, Asterisk ищет `exten => 1002` в контексте
`internal` (он указан в `[alice]` endpoint → `context = internal`),
находит `Dial(PJSIP/bob,30)` и звонит на текущий AOR боба.

## Подключение софтфона (программная эмуляция IP-телефона)

Любой SIP-клиент подойдёт — Zoiper, Linphone, MicroSIP (Windows),
встроенный softphone в Wireshark для отладки и т.п.

Параметры регистрации:
- Сервер/Domain: IP хоста, где запущен Docker (не `localhost` внутри
  контейнера — снаружи это адрес вашей машины)
- Порт: `5061` (см. docker-compose.yml — проброшен с 5060 контейнера)
- Транспорт: UDP
- Пользователь: `alice` / Пароль: значение `SIP_ALICE_PASSWORD` из `.env`
- Второй профиль аналогично для `bob`

## Физический IP-телефон

Если телефон физический и находится в той же локальной сети — те же
параметры, что для софтфона. Единственное отличие: `rtp.conf` уже
открывает диапазон 10011-10021, его должно хватить на 1 звонок;
если телефон за NAT — потребуется `external_media_address` в
`pjsip.conf` (пока не настроено, для учебного стенда без выхода в
интернет это не требовалось по ТЗ п.5.7 "предпочитать локальную работу").

## Если звонок проходит, но нет звука / звонок сразу обрывается

Это НЕ баг конкретного номера (600/601/1002 и т.д.) — почти всегда это
проблема с `EXTERNAL_MEDIA_ADDRESS` (см. `.env`). Механика: Asterisk в
Docker по умолчанию указывает софтфону "шли голос на мой внутренний
IP в docker-сети" — а этот адрес снаружи контейнера недостижим. SIP-
сигнализация при этом отрабатывает нормально (дозвон/ответ проходят),
а голоса нет — и многие софтфоны сами сбрасывают звонок, не получив
медиа в течение нескольких секунд. Это выглядит именно так, как в
вопросе "приходит вызов, но при ответе сбрасывается, звука нет".

Проверка/исправление:

1. В `.env` укажите `EXTERNAL_MEDIA_ADDRESS`:
   - софтфон на той же машине, что Docker — оставьте `127.0.0.1`
     (значение по умолчанию);
   - софтфон на другом устройстве в сети — впишите LAN-IP этой машины
     (`hostname -I` на Linux, или обычный IP машины в настройках сети
     на macOS/Windows).
2. Пересоберите и перезапустите: `docker compose up --build -d`
   (конфиг — шаблон, рендерится заново при старте контейнера).
3. Убедитесь, что диапазон RTP (`10011-10021/udp`) не блокируется
   локальным файрволом.
4. Для точной диагностики — смотрите SIP/RTP-трафик в консоли Asterisk:
   ```bash
   docker exec -it telephony-stage2-asterisk asterisk -rvvv
   pjsip set logger on
   ; # теперь наберите номер с софтфона и смотрите на IP в SDP (строка c=)
   ```
   Если там внутренний docker-адрес (обычно `172.x.x.x`) — это
   подтверждает причину выше.

## Ручная проверка

```bash
cp .env.example .env
docker compose up --build -d

# Вариант A — без второго софтфона:
# зарегистрируйте alice в любом softphone, наберите 600 (echo) и 601 (тон).

# Вариант B — оба аккаунта:
# зарегистрируйте alice и bob в двух клиентах, наберите с alice номер 1002.
```

Автоматическая проверка без софтфона (через AMI Originate):
`tests/test_stage2_sip_call.py` — инициирует звонок на echo-контекст и
проверяет по событиям AMI, что канал поднялся и корректно завершился.
