# Тестирование проекта в PyCharm

Пошаговая инструкция под Windows и PyCharm. Всё, что ниже, работает без модулей
остальных участников команды: ML и телефония заменены заглушками.

Если что-то пойдёт не так — раздел [«Если не запускается»](#9-если-не-запускается)
в конце и раздел 14 в [`TESTING.md`](TESTING.md).

---

## 0. Что уже готово в вашем проекте

|---|---|

## 1. Доустановить зависимости

Откройте терминал в PyCharm (**Alt+F12**) — он сам активирует `.venv`, в начале
строки должно быть `(.venv)`.

```powershell
pip install -r requirements-dev.txt
```

Без `openpyxl` не работают выгрузка в XLSX и импорт классификатора, без `locust` —
нагрузочный тест. Остальное уже стоит.

---

## 2. Создать `.env` и кнопки запуска

```powershell
copy .env.example .env
xcopy /E /I /Y docs\pycharm\runConfigurations .idea\runConfigurations
```

Первая команда создаёт файл настроек: там уже прописаны пользователь `dds112`,
пароль `dds112` и обе базы — ровно то, что поднимет контейнер на следующем шаге.
Вторая кладёт в проект семь готовых конфигураций запуска; PyCharm подхватывает их
сам, иногда после **File → Reload All from Disk**.

> `.env` и `.idea` лежат в `.gitignore`: настройки у каждого свои и в репозиторий
> не попадают. Поэтому конфигурации хранятся в `docs/pycharm/` и копируются.

> **Для учебного контура, а не для эксплуатации.** В `.env` стоит отладочный
> `SECRET_KEY`. Перед реальным развёртыванием замените его:
> `python -c "import secrets; print(secrets.token_hex(32))"`.

## 3. Поднять базу данных

Это единственное, что мешает проекту запуститься. Два пути — выбирайте любой.

### Путь А (рекомендую): база в контейнере

Не нужен пароль суперпользователя PostgreSQL, ничего не ставится в систему.
Нужен только запущенный Docker Desktop.

```powershell
docker compose up -d postgres
docker exec -it dds112-postgres psql -U dds112 -c "CREATE DATABASE dds112_test OWNER dds112;"
```

Первая команда поднимает PostgreSQL 16 с пользователем `dds112` и паролем `dds112` —
ровно то, что прописано в вашем `.env`. Вторая создаёт отдельную базу для тестов.

Проверить, что контейнер живёт:

```powershell
docker ps
```

В списке должен быть `dds112-postgres` со статусом `healthy`.

### Путь Б: локальный PostgreSQL

Нужен пароль суперпользователя `postgres` — тот, который задавался при установке.
Если помните:

```powershell
psql -U postgres -c "CREATE USER dds112 WITH PASSWORD 'dds112' CREATEDB;"
psql -U postgres -c "CREATE DATABASE dds112 OWNER dds112;"
psql -U postgres -c "CREATE DATABASE dds112_test OWNER dds112;"
```

Если не помните — не мучайтесь, идите путём А. Сброс пароля описан в разделе 14
[`TESTING.md`](TESTING.md), но это дольше и рискованнее.

> **Если ставите свой пароль вместо `dds112`** — впишите его в `.env` в двух местах:
> `POSTGRES_PASSWORD` и внутри `TEST_DATABASE_URL`.

## 5. Смотреть тесты глазами

Нажмите **2 Все тесты** — PyCharm откроет панель с деревом тестов вместо простыни
текста в консоли. Что там полезно:

* **зелёная галочка / красный крест** у каждого теста — видно, что именно упало;
* клик по упавшему тесту → справа сравнение ожидаемого и полученного;
* **кнопка ⟳ (Rerun Failed Tests)** — перезапустить только упавшие, а не все 79;
* **Ctrl+Shift+F10** на конкретном тесте в редакторе — запустить один тест;
* правый клик по тесту → **Debug** — остановиться на точке останова внутри кода.

Имена тестов написаны по-русски в docstring: в панели видно, что проверяется,
без чтения кода. Например: «Пропуск 30 секунд помечает карточку "Не оповещено",
но не закрывает её».

### Запустить часть тестов

Правый клик по файлу в дереве проекта → **Run 'pytest in …'**. Или создайте копию
конфигурации «2 Все тесты» и поменяйте в ней **Target** на нужный файл:

| Файл | Что проверяет |
|---|---|
| `test_training_flow.py` | сквозной цикл: занятие → карточка → оценка → отчёт |
| `test_workplaces_and_stream.py` | рабочие места, поток карточек, отработки |
| `test_routing_and_scoring.py` | маршрутизация по району, веса оценки, адреса |
| `test_response_statuses.py` | автомат статусов АРМ-112, норматив 30 секунд |
| `test_security_and_norms.py` | безопасность и дефекты, найденные при ревью |

## 6. Ручная проверка через Swagger

Нажмите **1 Сервер**, дождитесь в консоли `Application startup complete`, откройте
<http://localhost:8000/docs>.

1. Разверните `POST /api/v1/auth/login`, нажмите **Try it out**, введите
   `{"username": "teacher", "password": "Teacher#2026"}` → **Execute**.
2. Скопируйте `access_token` из ответа.
3. Нажмите кнопку **Authorize** справа вверху, вставьте токен, **Authorize** → **Close**.
4. Дальше любой запрос идёт от имени преподавателя.

Учётные записи: `teacher / Teacher#2026`, `student / Student#2026`,
`student2 / Student#2026`, `admin / Admin#2026`.

> **Совет.** Для проверки ролей держите два окна: обычное и приватное. В приватном
> войдите под `student`. Иначе придётся переавторизовываться на каждом шаге.

Подробные сценарии ручной проверки — в [`TESTING.md`](TESTING.md), разделы 2–13.

## 8. Отладка: остановиться внутри кода

Самое полезное для разбора логики — точка останова в ядре учебного процесса.

1. Откройте `app/services/training.py`, найдите `async def issue_next_card`
   (**Ctrl+F12** → поиск по файлу).
2. Кликните слева от номера строки — появится красная точка.
3. Запустите **1 Сервер** через **Debug** (значок жука вместо ▶).
4. В Swagger вызовите `POST /training/lessons/{id}/next-card`.
5. PyCharm остановится на точке останова: слева видны все переменные, можно
   пошагово пройти выдачу карточки (**F8** — следующая строка, **F7** — внутрь).

Так же отлаживаются тесты: точка останова + правый клик по тесту → **Debug**.

## 9. Если не запускается

**`ModuleNotFoundError: No module named 'openpyxl'`** — не доустановлены
зависимости, вернитесь к шагу 1.

**`ConnectionRefusedError` / `[Errno 111]` при миграциях или тестах** — база не
поднята. Путь А: `docker ps` — контейнера нет, поднимите заново. Путь Б: проверьте
службу PostgreSQL в `services.msc`.

**`password authentication failed for user "dds112"`** — пароль в `.env` не совпадает
с реальным. Либо приведите `.env` к настоящему паролю, либо смените пароль роли:
`psql -U postgres -c "ALTER USER dds112 PASSWORD 'dds112';"`.

**`database "dds112_test" does not exist`** — тестовая база создаётся отдельно,
команда в шаге 3.

**`WinError 64: Указанное сетевое имя больше не доступно`** — несовместимость
asyncpg со стандартным циклом событий Windows. Исправлено в `app/core/runtime.py`;
если ошибка появилась, значит запускается старый код: перезапустите PyCharm.

**Кракозябры в консоли PyCharm** — в конфигурациях запуска уже стоит
`PYTHONIOENCODING=utf-8`. Если всё равно: **File → Settings → Editor → File Encodings**,
везде поставить UTF-8.

**`[Errno 10048] address already in use`** — порт 8000 занят прошлым запуском.
Остановите старую конфигурацию (красный квадрат) либо:
`netstat -ano | findstr :8000`, затем `taskkill /PID <номер> /F`.

**Тесты падают все разом с ошибкой подключения** — сначала проверьте саму связь,
а не тесты:

```powershell
python -c "import asyncio,asyncpg; asyncio.run(asyncpg.connect('postgresql://dds112:dds112@localhost:5432/dds112_test'))"
```

Молча отработало — база в порядке, дело в другом. Упало — проблема в окружении.
