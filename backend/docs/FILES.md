# Карта проекта: за что отвечает каждый файл

Раздел 2 «Backend» из файла распределения задач. Всего 41 таблица в базе,
маршрутов API — больше 140, 38 атомарных прав, 79 автотестов.

Читать так: поток запроса идёт сверху вниз —
`api → services → repositories → models → PostgreSQL`, а `core` и `integrations`
подключаются сбоку. Логика живёт в `services`, SQL — в `repositories`,
в `api` только разбор запроса и проверка прав.

## Корень: как это запускается

| Файл | За что отвечает |
|---|---|
| `README.md` | Точка входа для человека: быстрый старт, архитектура, покрытие ТЗ, ограничения |
| `requirements.txt` | Рабочие зависимости: FastAPI, SQLAlchemy 2.0, asyncpg, Alembic, reportlab, openpyxl |
| `requirements-dev.txt` | Только для разработки: pytest, ruff, locust |
| `pyproject.toml` | Настройки ruff и pytest (`asyncio_mode=auto` — тесты async без декораторов) |
| `alembic.ini` | Конфигурация миграций |
| `.env.example` | Образец настроек со комментариями к каждой переменной. `.env` создаётся из него |
| `Dockerfile` | Сборка образа backend |
| `docker-compose.yml` | Только наша часть: backend + PostgreSQL. Для самостоятельной работы |
| `docker-compose.stack.yml` | **Весь комплекс из четырёх частей** (п.4.4 ТЗ): профили `ml`, `frontend`, `telephony`, `full` |
| `.dockerignore`, `.gitignore` | Что не попадает в образ и в репозиторий |
| `locustfile.py` | Сценарий нагрузочного теста: 100 сессий, вход → занятие → карточка → сдача |

## `app/` — приложение

### Точка входа и конфигурация

| Файл | За что отвечает |
|---|---|
| `main.py` | Создание FastAPI-приложения: middleware, обработчики ошибок, CORS, `X-Request-ID`, запуск и остановка фоновых задач |
| `core/config.py` | Все настройки одним объектом `settings` (pydantic-settings). Читает `.env`, собирает DSN, прячет пароль от аргументов `pg_dump` |
| `core/runtime.py` | **Совместимость с Windows**: переключает цикл событий на `WindowsSelectorEventLoopPolicy` — без этого asyncpg падает с `WinError 64` |
| `core/logging.py` | Структурированные логи в JSON: уровень, `request_id`, пользователь, длительность |
| `core/exceptions.py` | Единый формат ошибки: машинный `code`, человеческое `message`, `request_id`. Фронт разбирает по `code` |
| `core/pagination.py` | Постраничная выдача списков: `page`, `size`, `total` |

### Предметная область и права

| Файл | За что отвечает |
|---|---|
| `core/arm112.py` | **Памятка «Работа на АРМ-112» в виде кода**: 34 поля карточки в 8 разделах, обязательные поля, формат адреса, матрица ЕКП (какие службы оповещать по категории), запрещённые статусы для службы 103, построение списка оповещения |
| `core/permissions.py` | Каталог 38 прав вида `object:action` и наборы по умолчанию для роли. Источник правды для RBAC |
| `core/security.py` | Пароли (bcrypt), JWT access/refresh, второй фактор TOTP, проверка стойкости пароля |

### База данных

| Файл | За что отвечает |
|---|---|
| `db/session.py` | Асинхронный движок и фабрика сессий, `session_scope()` для работы вне запроса |
| `db/base.py` | Декларативная база SQLAlchemy |
| `db/mixins.py` | Примеси: UUID-идентификатор, `created_at`/`updated_at`, мягкое удаление |
| `db/types.py` | Переносимые типы колонок (JSON, UUID) — чтобы модели работали и на SQLite |

### `models/` — таблицы

| `scenario.py` | Учебные сценарии, эталоны заполнения, методические материалы |
| `training.py` | Ядро учебного процесса: **рабочие места**, назначения, занятия, участники, попытки, действия, статусы реагирования, **отработки** (звонки по карточке) |
| `grading.py` | Оценки, ошибки, результаты ИИ, рекомендации, история обучения, статистика |

| `audit.py` | Журнал аудита действий и системный журнал |
| `system.py` | Конфигурация в БД, состояние компонентов, резервные копии, вызовы, очередь outbox |

### `repositories/` — доступ к данным

Единственное место, где пишется SQL. Сервисы не знают о запросах.

| Файл | За что отвечает |
|---|---|
| `base.py` | Общие операции: получить, список с пагинацией, создать, обновить, мягко удалить |
| `users.py` | Пользователи, роли, права, группы |
| `content.py` | Классификатор, сценарии, материалы, карточки |
| `training.py` | Занятия, участники, попытки, действия, статусы |
| `grading.py` | Оценки, ошибки, рекомендации, история |
| `system.py` | Журналы, конфигурация, отчёты, телефония |

### `schemas/` — контракт API

Pydantic-модели запросов и ответов. Из них генерируется `openapi.json`, по которому
работает frontend. Файлы повторяют состав `models/`: `auth`, `user`, `catalog`,
`card`, `scenario`, `training`, `grading`, `report`, `system`, `common`.

### `integrations/` — стыки с чужими частями

Каждый внешний модуль спрятан за интерфейсом `Protocol`, у каждого есть
детерминированная заглушка. Переключение на реальный сервис — одна переменная в `.env`.

| Файл | За что отвечает |
|---|---|
| `ml_client.py` | **Контракт с участником 3 (ML)**: 7 методов — генерация карточки, коррекция, оценка, грамматика, аналитика, рекомендации, индексация материалов. Заглушка здесь же и служит эталоном формата ответа |
| `telephony_client.py` | **Контракт с участником 4**: инициировать вызов, состояние, завершение |
| `directory.py` | Локальная система управления доступом (LDAP/AD-шлюз контура) |
| `exchange.py` | Обмен карточками с внешними системами: JSON и XML |
| `outbox.py` | Буфер исходящих обращений: если ML недоступен, работа обучающегося не теряется — задача уходит в очередь и повторяется |
| `monitoring.py` | Метрики Prometheus и контроль нормативов (отклик 2 с, задержка VoIP 150 мс) |

### `workers/`

| Файл | За что отвечает |
|---|---|
| `maintenance.py` | Фоновые задачи: закрытие просроченных попыток, повтор из outbox, очистка журналов по срокам хранения, поиск карточек «Не завершено» |

## `migrations/` — схема базы

| Файл | За что отвечает |
|---|---|
| `env.py` | Окружение Alembic для асинхронного движка |
| `0001_initial_schema.py` | Базовая схема |
| `0002_response_statuses.py` | Статусы реагирования АРМ-112 и норматив первичного статуса |
| `0003_notification_list.py` | Список оповещения служб и служба обучающегося |
| `0004_attestation_directory.py` | Аттестация, переподготовка, интеграция с каталогом доступа |
| `0005_incident_classifier.py` | Таблица типов ЕКП и привязка карточки к типу |
| `0006_workplaces_stream_processings.py` | Рабочие места, поток карточек и срок отработки, отработки, справочник ДДС, веса сложности 1–10 |
| `0007_workplace_assignments.py` | Очередь заданий, розданных преподавателем по номерам АРМ |
| `0008_drop_progress_stats.py` | Удаление таблицы-кэша агрегатов: аналитика считает показатели на лету |

Все миграции проверены в обе стороны: `upgrade → downgrade → upgrade` без расхождений
между моделями и базой.
