# Учебное ПО для подготовки оператора ДДС с использованием ИИ

Учебная программная система для подготовки и оценки операторов дежурно-диспетчерских служб (ДДС).

Система предназначена для моделирования учебных ситуаций, работы с карточками происшествий, проведения тренировочных занятий, оценки действий обучающихся с использованием методов искусственного интеллекта и формирования аналитической отчётности.

> **Важно:** проект является учебным программным обеспечением. Он не является настоящей системой-112, не предназначен для обработки реальных экстренных вызовов и не должен использоваться как реальный диспетчерский центр.

## Возможности

Система предусматривает:

- эмуляцию учебных сценариев работы оператора ДДС;
- интерфейс, имитирующий работу с АРМ-112;
- учебные карточки происшествий;
- проведение занятий и сценариев;
- виртуальную IP-телефонию и SIP;
- работу с голосовыми данными;
- генерацию учебных сценариев с использованием ИИ;
- анализ и оценку действий обучающегося;
- анализ текста и грамматики;
- рекомендации по результатам обучения;
- статистику и аналитические отчёты;
- разграничение доступа пользователей по ролям;
- локальное развёртывание системы без необходимости внешнего интернет-доступа.

## Архитектура

Проект организован как monorepo и разделён на основные компоненты:

```text
frontend/      Пользовательский интерфейс
backend/       API, бизнес-логика и база данных
ml/            ИИ, анализ, генерация и оценка
telephony/     SIP, VoIP, голос и сценарии звонков
database/      Миграции и структура БД
deploy/        Развёртывание и мониторинг
docs/          Общая документация
```

Основные границы ответственности:

```text
Frontend
    ↓
что видит и нажимает пользователь

Backend
    ↓
данные и бизнес-логика

Python / ML
    ↓
что система понимает, генерирует, оценивает и рекомендует

Telephony / Docker
    ↓
как система запускается и как происходит учебный голосовой вызов
```

## Взаимодействие компонентов

Пример учебного сценария:

```text
Telephony
    ↓
создаёт входящий учебный вызов
    ↓
Backend
    ↓
создаёт или находит учебную сессию
    ↓
Frontend
    ↓
показывает вызов и карточку АРМ-112
    ↓
Обучающийся
    ↓
вводит информацию
    ↓
Backend
    ↓
сохраняет действие
    ↓
Python / ML
    ↓
оценивает действие относительно эталона
    ↓
Backend
    ↓
сохраняет результат
    ↓
Frontend
    ↓
показывает результат обучающемуся / преподавателю
```

## Запуск

Для локального развёртывания используется Docker Compose.

### Требования

- Docker
- Docker Compose
- Git

### Получение проекта

```bash
git clone <repository-url>
cd <repository-directory>
```

### Настройка окружения

Создайте локальный файл `.env` на основе:

```text
.env.example
```

Секреты и локальные настройки не должны добавляться в Git.

### Запуск

```bash
docker compose up --build
```

Конкретные параметры запуска компонентов описаны в соответствующих README:

- `frontend/README.md`
- `backend/README.md`
- `ml/README.md`
- `telephony/README.md`

## Разработка

Каждый участник команды преимущественно работает в своей директории:

```text
Frontend   → frontend/
Backend    → backend/
Python/ML  → ml/
Telephony  → telephony/
```

Изменения общих компонентов и архитектурных файлов необходимо согласовывать с командой.

Общие файлы:

```text
docker-compose.yml
docs/
database/
README.md
.env.example
```

## Данные

Проект предназначен для работы с учебными и обезличенными данными.

Реальные экстренные вызовы и конфиденциальные данные не должны использоваться в системе.

Временные аудиозаписи, логи, модели и другие генерируемые файлы не хранятся в Git.
