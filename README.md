# Учебный тренажёр ДДС

Локальный учебный тренажёр для подготовки операторов ДДС с имитацией
АРМ-112, учебных сценариев и голосовых вызовов.

Проект не обрабатывает реальные экстренные вызовы и не является системой-112.

## Назначение

Обучающийся принимает учебный входящий звонок, ведёт диалог с
виртуальным абонентом (или с реальным softphone/IP-телефоном), а система
фиксирует сессию: голос, текст, сценарий и результат отработки.

Основные возможности:

- локальный SIP/VoIP-контур (Asterisk, PJSIP, RTP);
- программный softphone и подключение физического IP-телефона;
- виртуальный учебный абонент со сценариями;
- запись вызовов (WAV / MP3) и воспроизведение;
- общее управление с аккаунта преподавателя;
- STT/TTS как сменные модули;
- диалоговый цикл: SIP → аудио → STT → ML/LLM API → TTS → SIP;
- привязка звонка к `session_id` / `scenario_id` / `call_id`;
- полный локальный стенд на Docker Compose без внешнего интернета в runtime.

## Архитектура

| Модуль | Роль |
|--------|------|
| **telephony** | SIP-сервер, звонки, RTP, запись, virtual caller, voice-service |
| **backend** | пользователи и роли, занятия, карточки, оценки, отчёты; API для frontend/ML/telephony |
| **frontend** | учебный интерфейс оператора (имитация АРМ) |
| **ml** | классификатор, генерация сценариев, оценка, реплики собеседников, LLM (Ollama) |
| **deploy** | nginx единой точки входа, надстройка телефонии для полного стенда |

## Стек

- SIP/PBX: Asterisk (PJSIP)
- Voice-сервисы: Python
- STT: faster-whisper
- TTS: Silero v5 (голоса baya, kseniya, xenia, aidar, eugene; модели © Silero Team, CC BY-NC 4.0 —
  некоммерческое использование), запасной — Piper (Irina, Dmitri, Denis; MIT)
- LLM: Qwen3 4B Instruct в Ollama (локально)
- API: REST/JSON
- БД: PostgreSQL
- Контейнеризация: Docker / Docker Compose
- Аудио: WAV, MP3; FFmpeg при конвертации
- Тесты: pytest, AMI (проверка Asterisk)

## Установка

### 1. Что скачать заранее

| Приложение | Зачем | Где взять |
|---|---|---|
| **Docker Desktop** (Windows 10/11) или **Docker Engine + compose** (Ubuntu 20.04+) | запускает весь стенд | [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/) · для Linux — [docs.docker.com/engine/install](https://docs.docker.com/engine/install/) |
| **Git** | скачать проект (можно обойтись: GitHub → Code → Download ZIP) | [git-scm.com/downloads](https://git-scm.com/downloads) |
| **MicroSIP** (Windows) | телефон рабочего места: голосовые вызовы через гарнитуру | [microsip.org/downloads](https://www.microsip.org/downloads) · на Linux / macOS — [Linphone](https://www.linphone.org/) |
| Chrome, Edge или Яндекс.Браузер | АРМ; режим «В браузере» — говорить в микрофон без софтфона | — |

Docker Desktop на Windows: при установке оставить галочку **WSL 2**, после установки перезагрузить
компьютер и один раз открыть Docker Desktop (дождаться «Engine running»). Проекту нужно 4 ядра,
12 ГБ ОЗУ и ~15 ГБ диска (с локальной LLM; рекомендация ТЗ для ИИ-сервера — 6 ядер и 32 ГБ).

MicroSIP не обязателен: без него звонки идут в режиме «В браузере» (микрофон или печать реплик).

### 2. Скачать проект и запустить

```bash
git clone https://github.com/N1ck6/112-Helper.git
```

Затем в папке `112-Helper`:

- **Windows** — двойной щелчок по `start.bat`;
- **Linux / macOS** — `sh start.sh` (или `./start.sh`).

Установщик сам:
1. проверит Docker (на Windows при необходимости запустит Docker Desktop);
2. создаст файл настроек `.env` со случайными паролями (если `.env` уже есть — не тронет его);
3. соберёт и запустит все сервисы;
4. дождётся готовности, откроет АРМ в браузере и покажет логины, пароли и данные для софтфона.

Первый запуск — 10–30 минут: скачиваются образы, модели распознавания и синтеза речи (~0.8 ГБ)
и локальная LLM Qwen3 4B (~2.5 ГБ). Модели докачиваются в фоне уже при открытом АРМ: до этого
проверка грамотности и рассказы заявителей идут по правилам. Интернет нужен только для первого
запуска, дальше стенд работает в закрытом контуре.

Повторный запуск `start.bat` / `start.sh` безопасен: `.env` и данные сохраняются.
Остановить — `docker compose stop`. Обновить до новой версии — `git pull`, затем снова `start.bat`.

> Если после `git clone` в папке нет `start.bat` — у вас старая копия проекта: выполните `git pull`
> в папке проекта или скачайте заново.

### 3. Свой `.env`

Все настройки и пароли стенда — в одном файле `.env` в корне проекта (шаблон с пояснениями —
`.env.example`). В GitHub он не загружается (в `.gitignore`): у каждой установки свои пароли.

- **Нет `.env`** — установщик создаст его сам.
- **Есть свой `.env`** (например, общий для класса или перенесённый со старого стенда) — положите
  его в корень проекта **до** запуска `start.bat`. Установщик его не перезапишет, только допишет
  параметры, которых в нём не хватает, и сгенерирует пустые пароли.
- Без установщика: скопировать `.env.example` в `.env`, заполнить пустые пароли и ключи,
  `docker compose up -d --build`. Пустой пароль или ключ — стенд не запустится (паролей по
  умолчанию нет).
- Сменили `ADMIN_PASSWORD`, `TEACHER_PASSWORD` или `STUDENT_PASSWORD` в `.env` — перезапустите
  `start.bat` / `./start.sh` (или `docker compose up -d`): новый пароль применится к учётной записи.
  Пароль, сменённый в интерфейсе, сохраняется, пока значение в `.env` не изменят.
  Пароль БД (`POSTGRES_PASSWORD`) на уже созданной базе менять нельзя.

### 4. Подключение MicroSIP (телефон рабочего места)

Данные для подключения установщик печатает в конце; они же в `.env`:
IP стенда — `EXTERNAL_MEDIA_ADDRESS`, порт — `EXTERNAL_SIGNALING_PORT` (5063), пароль — `TRAINEE_PASSWORD`.

1. MicroSIP → меню (стрелка вверху справа) → **Add Account**.
2. Заполнить:

   | Поле | Значение |
   |---|---|
   | Account Name | любое, например `АРМ ws01` |
   | SIP Server | `<IP стенда>:5063` (на том же ПК — тоже IP стенда или `127.0.0.1:5063`) |
   | Username | `ws01` — номер рабочего места, который обучающийся выбирает при входе в АРМ (`ws01`…`ws20`) |
   | Domain | `<IP стенда>:5063` |
   | Login | `ws01` |
   | Password | значение `TRAINEE_PASSWORD` из `.env` |
   | Transport | `UDP` |

3. Сохранить: внизу окна MicroSIP должно появиться **Online**, а в АРМ на панели «Телефон» —
   зелёная точка «готов».
4. Меню → **Settings**: кодеки PCMU / PCMA (G.711) должны быть включены; подавление тишины (VAD)
   выключить — иначе конец реплики определяется хуже.
5. Гарнитура — устройство записи и воспроизведения в Settings → Audio.

Каждому компьютеру класса — свой аккаунт (`ws02`, `ws03`, …) и тот же номер места при входе в АРМ.
Если софтфон на другом ПК не слышит собеседника, проверьте, что в `.env`
`EXTERNAL_MEDIA_ADDRESS` = IP стенда в локальной сети, и перезапустите `start.bat`.

### Если что-то не работает

- **«Docker не отвечает»** — откройте Docker Desktop и дождитесь «Engine running»; на Windows
  включите WSL 2 (Docker Desktop предложит сам) и виртуализацию в BIOS.
- **Порт занят** (`8080`, `5063`, `8000`…) — поменяйте `FRONTEND_PORT` и другие порты в `.env`.
- **Сайт не открывается с других ПК** — разрешите Docker Desktop в брандмауэре Windows для частной
  сети; адрес — `http://<IP стенда>:8080`.
- **MicroSIP «Request Timeout» / не регистрируется** — неверный IP или порт сервера, либо брандмауэр
  блокирует UDP 5063 и 10000–10059.
- **Звонок рвётся на ~32 секунде** — порт в SIP Server должен совпадать с `EXTERNAL_SIGNALING_PORT`.
- **Состояние и журналы** — `docker compose ps`, `docker compose logs -f api ml voice-service`.

### Адреса и учётные записи

| Адрес | Что это |
|---|---|
| http://localhost:8080 | АРМ (с других ПК класса — `http://<IP стенда>:8080`); через него же браузер ходит в `/api/`, `/telephony/`, `/ml/` |
| http://localhost:8000/docs | API backend (только с этого ПК) |
| http://localhost:8100/docs | API ML-сервиса (только с этого ПК) |
| `<IP стенда>:5063` UDP | SIP для софтфона рабочего места (`ws01`…`ws20`, пароль — `TRAINEE_PASSWORD` в `.env`) |

В локальную сеть открыты только АРМ (:8080), SIP и RTP. API backend и ML, API звонков, синтез речи,
записи разговоров и AMI Asterisk слушают только сам стенд (`SERVICE_BIND=127.0.0.1` в `.env`):
с других ПК класса записи и управление звонками недоступны.

**Учётные записи** (создаются при первом запуске, пароли — в `.env`): `admin` — администратор,
`teacher` — преподаватель, `student` и `student2` — обучающиеся. Новых пользователей заводит
администратор в разделе «Пользователи». При первом запуске тренажёр загружает классификатор
происшествий заказчика, генерирует через ИИ 12 утверждённых сценариев и добавляет в банк заданий
96 вызовов из билетов-задач заказчика (32 билета по 3 вызова) с эталонами карточек.

## Использование

### Как проходит тренировка

1. **Преподаватель** (`teacher`) → «Занятия»: режим «Оператор 112» или «Диспетчер ДДС», обучающиеся,
   категории → «Создать и запустить». «Сценарии» — сгенерировать новые через ИИ и утвердить эталоны;
   «Мониторинг» — кто за каким местом и как идёт; «Оценка ИИ» — подтвердить или исправить оценку;
   «Отчёты» — PDF/Excel/CSV по занятию.
2. **Оператор 112** (`student`, роль «Оператор», место ws01…ws20) → «Принять вызов»: карточка открывается,
   на телефон рабочего места звонит заявитель (софтфон, `<IP>:5063`) или разговор идёт «В браузере» —
   микрофоном или текстом. Содержание карточки скрыто: суть, адрес, пострадавших и имя нужно выяснить
   у заявителя. «Что случилось?» — поиск по классификатору происшествий («задым электрощит»).
   «Сохранить» → оценка ИИ: поля против эталона (ошибка в адресе — критическая), время, регламент.
3. **Диспетчер ДДС** (`student2`, роль «Диспетчер») → «Поток карточек»: «Принята / Не принята» за 30 с,
   затем ход работ до «Работы завершены» (3 мин на статус), звонки в службы кнопкой ☎. Закрытие
   карточки → оценка по регламенту памятки АРМ-112.
4. **Администратор** (`admin`): пользователи, состояние компонентов, журналы аудита, IP-телефония.

Каждой роли доступно только её (п.1.6 ТЗ, минимальные привилегии): обучающийся не видит сценарии и
эталоны карточек, администратор не правит учебный контент и оценки, преподаватель не управляет
учётными записями и системой.

Справка во время работы — вкладка «Справочная база» и выдвижная «Шпаргалка 112» у правого края.

Как связаны части (контракты — `telephony/API.md`, `backend/docs/INTEGRATION.md`):

```text
frontend ─/api/v1─> backend ──> PostgreSQL
    │                  ├─ генерация и оценка ──> ML   (что ML не умеет, 501 или сбой — правила backend)
    │                  └─ /api/v1/calls/originate ──> телефония (входящий 112 на рабочее место)
    └─/telephony/──> телефония ─/dialogue/turn─> ML ─(profile llm)─> Ollama
                         └─ события звонка ──> backend /api/v1/telephony/events (X-Telephony-Token)
```

Автотесты (нужен запущенный стенд; пароль AMI берётся из `.env`):

```bash
pip install -r tests/requirements.txt
```

```bash
pytest tests/ -v
```

## Структура репозитория

```text
telephony/      SIP/VoIP, запись, virtual caller, voice-service
backend/        API сессий, сценариев, статусов звонка
frontend/       UI учебного АРМ
ml/             LLM и сценарная логика
deploy/         nginx стенда, установщик (start.ps1, make_env.py)
tests/          pytest, AMI-клиент
data/           записи, логи сессий, резервные копии БД (локально)
start.bat       установка и запуск на Windows
start.sh        установка и запуск на Linux / macOS
.env.example    все настройки стенда с пояснениями (рабочая копия — .env)
```

Подробности по модулям — в `README.md` соответствующих каталогов `frontend/`, `backend/`, `telephony/`, `ml/`.

## Переменные и порты

Базовые сущности интеграции: `session_id`, `scenario_id`, `call_id`,
события старта/завершения звонка, статусы и ошибки.

Типичные порты локального стенда (точные значения — в `.env` / compose):

- SIP (UDP/TCP)
- RTP (диапазон UDP)
- AMI (управление/мониторинг Asterisk)
- HTTP voice-service / API backend / frontend
